# CGPRR | Local NEET AI Assistant (Track A)
## Design note | Final submission | 19 November 2026

### 1. Scope and architecture
This is a local, evidence-backed demonstration for NEET.info using **only synthetic data**: 8 fictional colleges and 64 fictional 2024-2025 cut-off records. It must not be used for actual counselling. The web interface calls a Python/FastAPI service. Two coordinated paths serve different questions:

- **Exact Q&A:** For a fully specified closing-rank question, FastAPI parses college, year, category and any stated additional constraints; it returns the matching CSV value directly with an exact citation (`cutoffs.csv#CR0005`), or refuses when unsupported/ambiguous.
- **RAG Q&A:** A local FastEmbed model (`BAAI/bge-small-en-v1.5`) embeds the question. Qdrant retrieves relevant row descriptions using cosine similarity and explicit metadata filters (default score threshold 0.48). A locally running open-weight model, served through LM Studio's OpenAI-compatible API, summarizes the supplied evidence. Responses without a retrieved citation, or containing numeric values not found in retrieved evidence, are refused. These checks are conservative; they are not a full semantic fact checker.
- **College explorer (Track A):** The `/predict` endpoint performs deterministic CSV filtering on state, year, category, course and quota, then includes fictional options where the entered rank is at or below the historical synthetic closing rank. Each result states its source and reason. There are no guarantees or eligibility probabilities.

**Simplified data flow:** Synthetic CSV -> structured lookup / FastEmbed -> Qdrant -> LM Studio -> citation and numeric checks -> FastAPI response -> browser. The predictor independently uses structured CSV filtering.

### 2. Models, environment and GPU sizing
The locally demonstrated model ID was **`qwen/qwen3-vl-4b`** (LM Studio). Its exact GGUF filename/quantization has not been recorded; do not assume a Q4 variant was tested. Development used a MacBook Air M1 with 8 GB unified memory; FastAPI ran natively, Qdrant in Docker, and LM Studio on the host. Embeddings were CPU-side. The main path requires no paid cloud LLM API. Initial model/package downloads do use the internet.

For the target **single RTX 6000 Ada with 48 GB VRAM** (an explicit generation and VRAM assumption), a quantized ~4B model could plausibly occupy a **roughly 4-10 GB inference memory budget** at modest contexts, depending on quantization, multimodal modules, KV cache and concurrency. This is a planning estimate, not a measurement or guarantee; exact VRAM and tokens/s require benchmarking on the chosen model and GPU. The design keeps room for concurrency but has not load-tested it. For reproducibility, the tested path is the native macOS API + Qdrant Docker + local LM Studio; fully containerized API deployment remains **unverified**.

### 3. Privacy, data separation and operations
The source CSVs reside in `data/`, vectors/payloads in a local Qdrant volume, the embedding cache locally, and logs in terminal/container logs. The application does not intentionally transmit inference prompts to external LLM APIs; local service configuration, updates and initial downloads should be reviewed for actual on-premises deployment. No student, doctor, patient, client or CGPRR internal records are included. In a production installation, separate business collections or instances, enforce per-business access control, authentication, audit and log retention, encryption and network restrictions. The demo has **no API authentication** and should remain bound to localhost, not exposed publicly.

### 4. Evaluation and measured results
On **19 November 2026 at 04:55 UTC**, `python scripts/evaluate.py --live` reported **16 PASS, 0 FAIL, 0 SKIP** using LM Studio model ID `qwen/qwen3-vl-4b`, FastEmbed `BAAI/bge-small-en-v1.5` and Qdrant collection `neet_knowledge`. The cases cover cited exact ranks, unavailable years and quotas, ambiguity/refusals, user-side instruction attacks, two live LLM summary queries and predictor outcomes. The actual report is committed as `docs/EVALUATION_RESULTS.md`. This is 100% on the defined test set, **not** evidence of universal accuracy. The live summary tests check citations and non-refusal; they do not verify each sentence's semantics. The rank checks and numeric grounding also have blind spots, including relationships between individually supported numbers.

### 5. Approximate cost, limitations and reproducibility
No paid LLM API is required. As an illustrative electricity assumption, a workstation drawing an average **0.3 kW** for **1 hour** uses **0.3 kWh**, costing **₹2.40** at **₹8/kWh**; this is not a measured power result and excludes hardware, staffing and maintenance. There is no RTX 6000 throughput benchmark. The synthetic cut-offs omit actual counselling rules, seat allocation complexities, real categories and current admissions data. The repository includes CSVs, data generator, Python/FastAPI code, frontend, Compose file, tests, evaluation script, README and demonstration guide. **AI coding assistance:** ChatGPT helped draft implementation and documentation; the candidate reviewed and executed the system. Quantization and Docker-mode performance must be confirmed separately before claiming them.
